JUNIE CLI 26.11.2 — THE PRIMARY JETBRAINS TOOL

Junie CLI is the main JetBrains tool used on this project. It is installed in the build environment and authenticates successfully with a JUNIE_API_KEY generated at junie.jetbrains.com/cli. The key itself is never committed; it lives outside the repo.

Resolved 24 Nov 2026: built-in JetBrains models now work. That block is gone: the hackathon codes arrived by email 24 Nov 2026 00:31 WIB (Devpost Credits) and were claimed the same day — All Products Pack plus AI Ultimate, each 2 months of access, valid through 22 Jan 2027 (per the license certificates; the Licenses page shows the next billing date as 23 Jan 2027). A test task on the default (built-in) model completed successfully 24 Nov 2026 01:16 WIB: authenticated, no license error. Note: the codes give 2 months each, not 6 — the earlier 6-month figure came from the hackathon page; the codes email is authoritative.

The fallback path: a BYOK custom model profile. Junie can run on a committed custom model profile, .junie/models/openrouter-nemotron.json, that routes Junie to the free tier of OpenRouter over the OpenAI Chat Completions format, using model nvidia/nemotron-3-ultra-550b-a55b:free. This was the working path on 23 Nov 2026; since the AI Ultimate claim it is the fallback, with built-in models primary. The profile references the API key only as an environment variable — no secret is stored in the repo. Note that Junie rejects passing an outside model ID on the command line (the model must be in Junie's own catalog); a custom profile is the only way to add one.

Two environment fixes were needed before this path worked at all. First, TLS: the sandbox routes egress through a MITM proxy, and Junie's bundled JVM rejected its certificate; the fix was importing the egress CA into Junie's bundled JVM truststore. Second, auth method: the junie-lite model needs interactive ACP login, not the API key — the API-key path is the one that works non-interactively.

To reproduce the setup: install Junie CLI, generate a key at junie.jetbrains.com/cli, export JUNIE_API_KEY and OPENROUTER_API_KEY (never commit them), then run: junie "Your task here" (built-in models, primary since 24 Nov 2026) — or, as fallback, junie --model custom:openrouter-nemotron "Your task here".

JETBRAINS AIR (JBCONTEXT) — ATTEMPTED, FAILED, NOT DONE

Air indexing is NOT done, and this text does not claim it is. jbcontext 0.9.22 (the Air CLI) is installed. On 23 Nov 2026 the full login was attempted: the browser completed the JetBrains OAuth authorization — the authorization code was obtained and the state matched — but delivering the callback to the CLI's localhost:62350 listener failed. Requests carrying code and state got empty responses (connection closed, no HTTP response), while a no-params request returned a normal 200 page. The CLI waited out its roughly 4-minute timeout, fell back to JetBrains Account login, and died with "OAuth login failed -- Unsupported HTTP version: muse:".

Root cause (from the jbcontext log): jbcontext's HTTP client cannot do CONNECT through the sandbox egress proxy — its own log shows "Analytics push failed: Failed to parse CONNECT response: unexpected EOF". Direct egress does not exist in this VM, so bypassing the proxy is impossible.

One remaining path is unverified: jbcontext login with a token (needs a JCP token from the JetBrains web console) plus --no-verify — and even then, index and search may still need the same broken HTTP client. Air is therefore treated as nice-to-have: Junie (the .junie/ directory plus the repo's AI_SHOWCASE.md) already satisfies the hackathon's JetBrains-tool requirement, and Air indexing is not on the critical path for the project.

Note: AI_SHOWCASE.md in the repo was updated on 23 Nov 2026 to record the diagnosed Air login failure described above, so it now agrees with this text.
