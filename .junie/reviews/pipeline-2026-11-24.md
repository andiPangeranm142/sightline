## Temuan yang masih terbuka

### Tinggi

1. **Posisi cast disajikan sebagai posisi placement.** `aggregate.py:603-606,630-632,943-958` mengelompokkan posisi pemain ketika cast, tetapi kartu menyebutnya “placements” dan respons menyarankan membersihkan sektor tersebut. Lokasi pemain bukan bukti lokasi trap. `n` dan persentase juga dihitung per ronde dengan cast, bukan per penggunaan; badge memakai penyebut semua ronde, sedangkan teks memakai ronde dengan ability. Contoh pada output lama: Trapwire tim 1079 di Haven. **Tindak lanjut:** ubah label dan respons menjadi sektor cast, ungkapkan numerator/denominator yang sesuai, atau gunakan data placement yang memang terukur.

2. **Profil Operator mencampur tim historis.** `aggregate.py:348-360,427-433,795-817`: counter dikunci oleh pemain dan map, sedangkan profil diberi satu `team_id` terakhir. Bila pemain berpindah tim, ronde dan kill tim terdahulu dapat diatribusikan ke tim terakhir. **Tindak lanjut:** agregasi menurut `(team_id, player_id, map)` dan revisi kontrak/filter frontend agar identitas tim historis dipertahankan.

3. **Konteks antar-game dapat bocor.** `aggregate.py:440-460,546-572`: snapshot `game-started-gameClock` mencatat pemegang Operator tanpa memeriksa game aktif; sebelum ronde baru dimulai snapshot game berikutnya dapat masuk ke ronde sebelumnya. Selain itu, round-start game baru tanpa nama map mempertahankan map dan bounds lama. **Tindak lanjut:** validasi game/ronde snapshot, reset konteks saat game berubah, dan abaikan atau laporkan event tanpa konteks map yang valid.

4. **Ukuran sampel kartu bukan denominator.** `aggregate.py:886-895,911-968`: `n` adalah jumlah ronde positif, sedangkan `frequency` memakai jumlah ronde yang diamati atau ronde agent; UI menyajikan `n` sebagai ukuran sampel. Misalnya 5 ronde positif dari 100 tidak memiliki ukuran sampel 5. **Tindak lanjut:** ekspor dan tampilkan numerator serta denominator secara eksplisit; uji setiap jenis kartu dan side.

5. **Agregat lama masih memuat ability nonbalistik.** `landing.py:41-75` sebelumnya memasukkan Gatecrash (tether di tanah), Curveball (melengkung), dan Cloudburst (dapat dikendalikan). `docs/data/landing-zones.json` saat ini memuat masing-masing 268, 64, dan 106 dari 3.250 titik *sampel tersimpan*, bukan dari seluruh cast. Allowlist sudah diperbaiki untuk run berikutnya, tetapi JSON lama belum berubah. **Tindak lanjut:** regenerasi dan validasi allowlist lainnya terhadap perilaku ability sebelum publikasi. Rujukan: [Gatecrash](https://wiki.playvalorant.com/en-us/Gatecrash), [Phoenix](https://playvalorant.com/en-us/agents/phoenix), [Jett](https://www.thespike.gg/valorant/agents/jett).

### Sedang

6. **Kualitas landing dan confidence belum terkalibrasi.** `landing.py:84-100` menambahkan `weight` interpolasi sebagai confidence, padahal weight hanya posisi waktu relatif antara dua frame, bukan akurasi; nilai 0,04 dan 0,96 diperlakukan berbeda meski sama jauhnya dari frame terdekat. Model tidak memperhitungkan dinding dan men-clamp landing di luar bounds ke tepi peta (`aggregate.py:693-710`). `VALIDATION.md:23,51` melaporkan 2.472 landing di-clamp dari 176.355 proyeksi pada run historis. **Tindak lanjut:** pakai heuristik jarak/waktu dan kualitas yang dijelaskan sebagai skor tidak terkalibrasi, evaluasi dengan ground truth bila tersedia, dan hindari menampilkan landing di luar bounds; geometri dinding memerlukan solusi terpisah.

7. **Agregasi nonspasial menghilangkan cast tanpa posisi.** `aggregate.py:591-605,627-644`: return sebelum counter tendency dan join supplement bila koordinat GRID tidak lengkap, walau cast dan supplement mungkin valid. **Tindak lanjut:** pisahkan counter dan join dari persyaratan koordinat; batasi pengecekan posisi pada output spasial.

8. **Numerator dan denominator ability dapat berasal dari populasi berbeda.** `aggregate.py:471-476,563-565,627-629,873-882,911-930`: agent cast dapat diketahui dari snapshot lain, tetapi denominator memakai `character` pada round-start; side tak dikenal masuk numerator total tetapi tidak denominator attack/defense. Snapshot/side tidak lengkap dapat menghasilkan rate salah atau di atas 100%. **Tindak lanjut:** ukur keduanya pada ronde agent/side terverifikasi yang sama dan laporkan data yang dikecualikan.

9. **Subsampling sistematis berpotensi bias.** `aggregate.py:775-792,991-1015` mengurutkan berdasarkan tim/pemain/ability/koordinat sebelum mengambil setiap item kedua. Dalam kelompok yang terurut ini titik awal lebih sering dipertahankan; ini bukan sampel acak uniform seperti klaim umum di `README.md:109-114`. Run historis melaporkan satu halving. **Tindak lanjut:** subsampling acak deterministik dari reservoir sebelum sorting, sambil menjaga representasi per map dan mengungkapkan metode akhirnya.

10. **Kegagalan input dan resume dapat menghasilkan sukses parsial.** `aggregate.py:714-726,1180-1186,1201-1218,1266-1298`: event file hilang dicatat sebagai gagal tetapi output tetap ditulis dan proses kembali 0; seri gagal juga dianggap selesai pada resume. Checkpoint tidak memvalidasi `--limit`, data-dir, atau cap yang berbeda. Supplement yang hilang juga dilewati tanpa penanda per seri. **Tindak lanjut:** gagal secara eksplisit sebelum mengganti output bila input wajib hilang, laporkan coverage supplement, retry kegagalan dan validasi konfigurasi checkpoint.

11. **Budget output tidak dijamin.** `aggregate.py:991-1015,1259-1277`: jika file yang tidak dapat disampling sudah terlalu besar atau kedua list tersisa paling banyak 100 item, loop berhenti dan tetap menulis meskipun melebihi budget; perubahan ukuran metadata setelah loop juga tidak diperiksa lagi. **Tindak lanjut:** verifikasi total akhir dan hentikan run sebelum menulis jika budget tidak dapat dipenuhi.

12. **Laporan validasi tidak sinkron dengan berkas yang ada.** `VALIDATION.md:38-46` menyebut ukuran `anti-strat`, `self-scout`, `landing-zones` berturut-turut 421.351, 15.826, dan 1.151.505 byte; ukuran aktual 365.845, 13.725, dan 1.210.004 byte. Total aktual 5.651.545 byte, bukan 5.650.653. `meta.json` masih cocok untuk coverage 337 seri, 848 game, 17.435 ronde dan 1.421.082 event, tetapi perbedaan ukuran berarti laporan tersebut tidak memverifikasi keseluruhan output saat ini. **Tindak lanjut:** buat ulang laporan dari run yang sama dengan seluruh agregat, idealnya dengan manifest/hash.

13. **Lokasi output bertentangan dengan hard rule.** `README.md:3-5,16`, `aggregate.py:1159-1161` dan frontend memakai `docs/data/`, sedangkan guidelines meminta agregat yang dikomit hanya di `data/aggregates/`. Mengubah lokasi memengaruhi publikasi GitHub Pages dan kontrak frontend. **Tindak lanjut:** sepakati dan implementasikan strategi publikasi yang memenuhi kedua kebutuhan sebelum mengomit agregat baru; review ini tidak menambah atau mengubah data mentah maupun agregat.

14. **Frame Zstandard terpotong dapat berakhir diam-diam.** `gridio.py:51-65`: `stream_reader.read()` dapat mengembalikan EOF tanpa error walau frame belum lengkap. Dalam uji sintetis, menghapus byte terakhir frame masih mengembalikan satu baris JSON lengkap dan satu baris JSON valid tanpa newline; pipeline akan menerima kedua baris tanpa mendeteksi frame terpotong. Pemotongan pada tengah JSON memang dapat memicu parse error, tetapi pemotongan di batas record tidak terdeteksi. **Tindak lanjut:** verifikasi integritas frame streaming/ukuran atau checksum input tanpa dekompresi ke disk dan uji file terpotong serta multi-frame.

### Rendah / tergantung kualitas input

15. **Input numerik rusak dan bounds tidak valid.** `landing.py:115-130` mengonversi `null` dengan `float()` sehingga dapat gagal, sementara komponen hilang menjadi nol dan NaN tidak ditolak. `gridio.py:154-176` masih memakai fallback 500 untuk sumbu dengan bounds tidak valid; perbaikan hanya menandai `in_bounds=False`, sehingga caller masih dapat menyimpan titik fallback. **Tindak lanjut:** validasi komponen wajib dan `math.isfinite`, serta lewati titik dengan bounds invalid; hitung dan laporkan record yang dikeluarkan.

16. **Nama metrik Operator lebih kuat daripada evidensinya.** `aggregate.py:479-489,575-583,805-817`: `buy_rate_by_round` mengukur kepemilikan yang terlihat, termasuk pickup/kill fallback, bukan pembelian. Posisi yang disampling dapat berulang meskipun UI menyebutnya unik. **Tindak lanjut:** sebut ownership yang teramati dan observasi posisi; tampilkan denominator dan deduplikasi hanya bila memang dimaksudkan.
