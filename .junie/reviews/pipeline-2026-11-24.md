# SIGHTLINE pipeline review — 2026-11-24

Translated to English from Junie's original Indonesian report (24 Nov 2026); content unchanged.

## Scope and status

- Reviewed `pipeline/README.md`, `VALIDATION.md`, `SELECTION.md`, `gridio.py`, `landing.py`, and `aggregate.py`, and compared the selection CSVs and existing aggregates. The hypothetical conditions below do not mean they have been proven to occur in the published data.
- Priorities reflect the risk of wrong decisions or data loss, not the frequency of events that have not yet been measured. Fixes requiring schema/methodology changes or aggregate regeneration are recorded as follow-ups, not applied in this review.
- Small fixes applied: zero/inverted bounds are no longer marked valid; `gap_exceeded` is not projected; projections that reach timeout without reaching ground are rejected; Gatecrash, Curveball, and Cloudburst removed from the ballistic allowlist. Reproduction tests added.
- **Existing aggregates have not been regenerated**; the app still loads the old results and findings relating to them still apply. Regeneration must address the findings below as well as the output-location rules before publication.

## Open findings

### High

1. **Cast positions are presented as placement positions.** `aggregate.py:603-606,630-632,943-958` groups player positions at cast time, but the cards call them "placements" and responses suggest clearing that sector. A player's location is not evidence of a trap location. `n` and percentages are also computed per round with a cast, not per use; the badge uses all rounds as denominator, while the text uses rounds with the ability. Example in the old output: Trapwire for team 1079 on Haven. **Follow-up:** change labels and responses to cast sectors, disclose the appropriate numerator/denominator, or use placement data that is actually measured.

2. **Operator profiles mix historical teams.** `aggregate.py:348-360,427-433,795-817`: counters are keyed by player and map, while the profile is given one last `team_id`. If a player changes teams, rounds and kills from earlier teams can be attributed to the last team. **Follow-up:** aggregate by `(team_id, player_id, map)` and revise the frontend contract/filter so historical team identity is preserved.

3. **Cross-game context can leak.** `aggregate.py:440-460,546-572`: the `game-started-gameClock` snapshot records Operator holders without checking the active game; before a new round starts, snapshots from the next game can enter the previous round. Additionally, a new game's round-start without a map name retains the old map and bounds. **Follow-up:** validate snapshot game/round, reset context when the game changes, and ignore or report events without valid map context.

4. **Card sample size is not the denominator.** `aggregate.py:886-895,911-968`: `n` is the number of positive rounds, while `frequency` uses the number of observed rounds or agent rounds; the UI presents `n` as the sample size. For example, 5 positive rounds out of 100 does not have a sample size of 5. **Follow-up:** export and display numerator and denominator explicitly; test each card type and side.

5. **Old aggregates still contain non-ballistic abilities.** `landing.py:41-75` previously included Gatecrash (ground tether), Curveball (curves), and Cloudburst (controllable). `docs/data/landing-zones.json` currently contains 268, 64, and 106 of these respectively out of 3,250 stored sample points, not out of all casts. The allowlist has been fixed for the next run, but the old JSON is unchanged. **Follow-up:** regenerate and validate the other allowlists against ability behavior before publication. References: [Gatecrash](https://wiki.playvalorant.com/en-us/Gatecrash), [Phoenix](https://playvalorant.com/en-us/agents/phoenix), [Jett](https://www.thespike.gg/valorant/agents/jett).

### Medium

6. **Landing quality and confidence are uncalibrated.** `landing.py:84-100` adds interpolation `weight` as confidence, although weight is only relative time position between two frames, not accuracy; values 0.04 and 0.96 are treated differently although equally far from the nearest frame. The model does not account for walls and clamps landings outside bounds to the map edge (`aggregate.py:693-710`). `VALIDATION.md:23,51` reports 2,472 landings clamped out of 176,355 projections on the historical run. **Follow-up:** use a distance/time and quality heuristic described as an uncalibrated score, evaluate against ground truth if available, and avoid displaying landings outside bounds; wall geometry requires a separate solution.

7. **Non-spatial aggregation drops casts without positions.** `aggregate.py:591-605,627-644`: returns before tendency counters and supplement join when GRID coordinates are incomplete, although the cast and supplement may be valid. **Follow-up:** separate counters and join from the coordinate requirement; restrict position checks to spatial outputs.

8. **Ability numerator and denominator may come from different populations.** `aggregate.py:471-476,563-565,627-629,873-882,911-930`: the casting agent can be known from another snapshot, but the denominator uses `character` at round-start; unknown side enters the total numerator but not the attack/defense denominators. Incomplete snapshot/side can produce wrong rates or rates above 100%. **Follow-up:** measure both on the same verified agent/side rounds and report excluded data.

9. **Systematic subsampling may be biased.** `aggregate.py:775-792,991-1015` sorts by team/player/ability/coordinates before taking every second item. Within these sorted groups the first point is more often retained; this is not a uniform random sample as the general claim in `README.md:109-114`. The historical run reported one halving. **Follow-up:** deterministic random subsampling from the reservoir before sorting, while preserving per-map representation and disclosing the final method.

10. **Input failures and resume can produce partial success.** `aggregate.py:714-726,1180-1186,1201-1218,1266-1298`: a missing event file is logged as failed but output is still written and the process returns 0; failed series are also treated as complete on resume. Checkpoints do not validate `--limit`, data-dir, or different caps. Missing supplements are also skipped without a per-series marker. **Follow-up:** fail explicitly before replacing output when required input is missing, report supplement coverage, retry failures and validate checkpoint configuration.

11. **Output budget is not guaranteed.** `aggregate.py:991-1015,1259-1277`: if non-sampleable files are already too large or both remaining lists have at most 100 items, the loop stops and still writes even if over budget; metadata size changes after the loop are also not re-checked. **Follow-up:** verify the final total and stop the run before writing if the budget cannot be met.

12. **Validation report is out of sync with existing files.** `VALIDATION.md:38-46` states `anti-strat`, `self-scout`, `landing-zones` sizes of 421,351, 15,826, and 1,151,505 bytes respectively; actual sizes are 365,845, 13,725, and 1,210,004 bytes. Actual total is 5,651,545 bytes, not 5,650,653. `meta.json` still matches for coverage of 337 series, 848 games, 17,435 rounds and 1,421,082 events, but the size differences mean the report did not verify the entire current output. **Follow-up:** regenerate the report from the same run as all aggregates, ideally with a manifest/hash.

13. **Output location conflicts with the hard rule.** `README.md:3-5,16`, `aggregate.py:1159-1161` and the frontend use `docs/data/`, while the guidelines require committed aggregates only in `data/aggregates/`. Changing the location affects GitHub Pages publication and the frontend contract. **Follow-up:** agree on and implement a publication strategy that meets both needs before committing new aggregates; this review does not add or change raw data or aggregates.

14. **Truncated Zstandard frames can end silently.** `gridio.py:51-65`: `stream_reader.read()` can return EOF without error even if the frame is incomplete. In a synthetic test, deleting the last byte of a frame still returned one complete JSON line and one valid JSON line without a newline; the pipeline would accept both lines without detecting the truncated frame. Truncation in the middle of JSON can indeed trigger a parse error, but truncation at a record boundary is undetected. **Follow-up:** verify streaming frame integrity/input size or checksum without decompressing to disk and test truncated and multi-frame files.

### Low / input-quality dependent

15. **Corrupt numeric input and invalid bounds.** `landing.py:115-130` converts `null` with `float()` so it can fail, while missing components become zero and NaN is not rejected. `gridio.py:154-176` still uses fallback 500 for axes with invalid bounds; the fix only marks `in_bounds=False`, so callers can still store fallback points. **Follow-up:** validate required components and `math.isfinite`, and skip points with invalid bounds; count and report excluded records.

16. **Operator metric names are stronger than the evidence.** `aggregate.py:479-489,575-583,805-817`: `buy_rate_by_round` measures observed ownership, including pickup/kill fallback, not purchases. Sampled positions can repeat although the UI calls them unique. **Follow-up:** say observed ownership and position observations; show denominators and deduplicate only when actually intended.

The current fix chooses to skip those records rather than using the nearest frame; the number skipped is not yet reported.
