# SIGHTLINE frontend review — 2026-11-24

Translated to English from Junie's original Indonesian report (24 Nov 2026); content unchanged.

## Scope and status

- Reviewed `docs/index.html`, `docs/css/style.css`, `docs/js/app.js`, and `docs/js/maps.js`; `docs/js/data.js` and aggregates were read as context. Priorities below indicate potential impact, not measured frequency.
- Data, numbers, and on-screen claims were not changed. Findings requiring changes to data display, metric definitions, or interpretation are recorded as follow-ups.

## Open findings

### High

1. **Operator profile can come from a previous team.** `docs/js/app.js:265-269,461-481`: when the new team has no profile, the old `operatorPlayerId` is not cleared and the profile search runs across all teams. The previous profile can remain displayed in the context of the new team; the global search is also ambiguous if a player ID exists on more than one team. The current aggregates have four teams without an Operator profile. **Follow-up:** clear the selection when no profile exists and search only within the active team's profiles; test team switching and repeated IDs.

2. **Heatmap cells at the map edge can fall outside the map.** `docs/js/app.js:300-312,324-347`: the bin index is clamped to 999, not the last index of the grid. For coordinate 1000 and cell size 50, the cell center becomes 1025; hard-numbers labels and part of the heatmap can be cut off. The current aggregates have 113 points with x or y >= 1000. **Follow-up:** clamp the index to the last cell and test the 0/1000 boundaries; grouping changes can alter per-cell numbers and need approval.

3. **Landing-zone filter does not match the cast filter.** `docs/js/app.js:289-297,362-365`: cast points follow player, agent, ability, side, and round time, while estimate zones follow only team and map. Zones can be misread as the result of the active filters; the empty overlay (`index.html:152-155`, `app.js:316-319`) can also cover zones even when zones are available. **Follow-up:** explain the scope and define filter behavior according to the available fields; do not assume unsupported filters have been applied.

4. **Some Operator claims require data/methodology review.** `docs/js/app.js:505-522,593-602`: the `setup_positions` count is called unique positions without frontend deduplication; the scout-card fallback calls all positions defense although setup data contains side. The chart says buy-rate, while the pipeline review found a metric derived from observed ownership. **Follow-up:** validate deduplication, side, and denominators together with the pipeline before changing labels or claims. See also `.junie/reviews/pipeline-2026-11-24.md`.

### Medium

5. **Spatial information and charts are not fully accessible.** `docs/index.html:151,188,198` gives generic names to `role="img"` visuals; `docs/js/app.js:356-392,512-522` limits landing-zone visual labels and stores the remaining confidence in SVG tooltips, while bar values exist only in `div` tooltips. That information has no complete text alternative accessible via keyboard/screen reader. Individual estimate zones also do not display `n`; the current zone schema provides no sample-size field. **Follow-up:** determine and provide a verifiable sample size, plus a text/table representation with ESTIMATE labels and confidence; test with assistive technology.

6. **Loading and error status is not announced.** `docs/index.html:40-55` and `docs/js/app.js:127-142` update or display messages without an already-available live region. Screen readers can miss failures and partial warnings. **Follow-up:** use a live region that exists before the update and verify announcements in the browser and screen reader.

7. **Operator markers depend on color.** `docs/css/style.css:602-603,705-712` and `docs/index.html:190-193` use the same shape for attack and defense. **Follow-up:** distinguish shape or pattern and adjust the legend, without changing source positions.

8. **Marker anti-overlap declaration is not always met.** `docs/js/app.js:438-458` checks the initial candidate before clamping, then still accepts a position after a maximum of 24 attempts. Synthetic example `(25,75)` and `(0,110)` do not collide before clamping, but are 35 apart after clamping, below `MIN_SEP` 42. **Follow-up:** clamp before checking and define behavior for dense areas when there is not enough room.

## Small fixes applied

- The fatal-error path hides main content; the no-JavaScript message replaces a loading indicator that never completes.
- Round-time buttons have `aria-pressed` that follows clicks and reset. Team, player, and map names in discovered markup paths are escaped without changing the displayed text.
- The card grid can shrink on narrow screens; switch transitions follow reduced motion; print selectors no longer depend on `:has()`.
- Contrast of white button text and brand text on white cards improved. The brightest solid-color calculation yields about 5.88:1, or about 4.90:1 on the hover estimate; actual appearance has not yet been tested in a browser.

## Review verification

- `node --test docs/tests/frontend.test.js`: 4 tests passed; reproduction of fatal error, button status, and escaping failed before the fixes. The tests also run initialization and filter interactions with real aggregates using a minimal DOM.
- `node --check` for the three JavaScript files and `git diff --check` passed. Aggregate checking was done only by reading existing JSON files.
- Browser, screen reader, responsive layout, reduced motion, and print flow have not been tested end-to-end in this environment; minimal DOM tests are not a substitute for that testing.
